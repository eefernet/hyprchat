# Daedalus local-model evaluation — 2026-09-10

This evaluates the opt-in persistent workflow in an isolated Codebox worker. Production application files were not deployed and production services were not restarted. Worker dependencies and browser prerequisites were prepared separately. The feature remains disabled by default.

Raw JSON reports contain local run and deployment details and are excluded from Git. Filenames below refer to local evidence in this directory; this summary and the benchmark tooling remain tracked.

## Conditions

- Local Ollama 0.30.7 inference only; Qwen3 Coder 30B (30.5B MoE) and Devstral 24B (23.6B), both Q4_K_M. Model digests are recorded in the JSON.
- Explicit evaluation allowance: 600 seconds and 120 model calls per fixture, with 20 Builder turns per attempt. The product default remains 3,600 seconds.
- Context: 65,536 tokens, 4,096 completion tokens, 5% headroom, compaction enabled at 75% of the available input budget. These are recorded settings, not hidden caps.
- Browser interaction/assertion timeout: 15 seconds per step, configurable independently of the command timeout.
- Pinned worker dependencies and exact evaluated source hashes are recorded in the local result file `daedalus-2026-09-10.json`.
- Codebox DNS resolution was unavailable. The isolated worker used a prepared offline pytest wheel cache; no global production pip or DNS settings were changed.
- Golden assertions ran outside the model context against downloaded accepted archives. The three large fixtures contain 100K, 500K, and 1M lines of unrelated padding source; this is not a representative production-monorepo benchmark.

## Observed failure modes

- Qwen lookup (1M lines): the function was edited to preserve falsy values, but the generated test file printed examples without runnable assertions; unittest discovered no tests. This is not evidence of failed repository navigation.
- Devstral lookup (1M lines): the final workspace still contained the original falsy-value bug after its call allowance was exhausted.
- Qwen grouping: false acceptance. The delivered function treated `key` as a callback, although the requested API used `item[key]` with a property name. The archive-level check failed with `TypeError: key is not a function`.
- Devstral ranges: false acceptance. The delivered implementation mutated an input range while merging; the task explicitly required preserving inputs. Its own checks and Acceptance missed this, while the independent archive-level assertion failed.
- Qwen temperature: the rejection incorrectly described the standard `(f - 32) * 5 / 9` conversion as wrong. Review-model judgments need executable grounding as well as source access.
- Qwen ranges: Acceptance claimed the function lacked an export, although the inspected revision contained `export function mergeRanges`. Its generated tests also used `console.assert`, which does not make Node exit unsuccessfully when an assertion fails. The rejection rationale and test quality are separate issues.
- Qwen tags: the Architect supplied a browser flow for a Python utility. The controller recovery correction and separate checkpoint continuation are described below; this original failure remains scored.
- Devstral pagination: the evaluated controller reported 39 calls after its deadline; the worker ledger recorded 43. The subsequent controller fix waits for cancellation acknowledgement and final usage.

## Checkpoint continuation

A separate run used the corrected controller to Continue the original Qwen tags job from its saved workspace. The allowance advanced from 1 to 2. It returned to planning, coding, and checking, but the model repeated the incompatible browser requirement. The repeated-plan guard blocked it after 40 new calls and 180 seconds, with no accepted artifact. This validates continuation and the repeat guard, not successful task completion. The original matrix failure is unchanged. Separate result and event evidence is retained locally in `daedalus-2026-09-10-plan-recovery.json`.

## Interpretation

Earlier partial 32K and 64K diagnostics are retained locally as `daedalus-2026-09-10-32k-diagnostic.json` and `daedalus-2026-09-10-64k-diagnostic.json` for traceability. The 64K diagnostic exposed SDK text-tool serialization and stop-word handling defects that were fixed before this full evaluation. These runs use different source candidates and are not a controlled context-size comparison.

The controller, Settings policy, repository navigation, verification, and artifact fences are implemented. These model results determine rollout readiness separately from the deterministic software tests. A blocked attempt produces no accepted artifact. Any false acceptance is a release blocker and remains visible in the table and raw evidence.

## Work required before promotion

- Add independently executable checks for explicit API and input-preservation requirements; tests generated by the Builder are insufficient evidence when they implement the same mistaken interpretation.
- Stop or reframe repeated identical inspections when they add no new evidence. Devstral exhausted its configuration-case allowance in the review path despite reaching Acceptance. Recorded events confirm repeated reads of the same file/hash; observed prompt usage was well below the configured context window.
- Include relevant source excerpts in the initial Acceptance context, selected from task references and changed files within the configured budget. The evaluated context begins with inventory and paged inspection tools; Qwen sometimes declined to inspect and rejected work for missing source evidence.
- Require Acceptance findings to cite inspected source and executable evidence. The current evaluation contains both false acceptance and an incorrect rejection rationale.
- Re-run the entire matrix after those changes, including a comparable legacy baseline and representative real-project fixtures. Keep the default flag off until all promotion conditions pass.
